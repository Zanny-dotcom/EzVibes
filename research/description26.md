# Research #26 — Linear / Vercel / Geist Design System Aesthetics (2025–2026) for the EZvibes Prompt Vault

> Research agent #26 of 30. Focus: applying the modern SaaS "gold standard" — Linear, Vercel, Geist — to the EZvibes's prompt vault panel.

Status: maximum-dump.

---

## 0. Executive direction for the EZvibes vault

The "Linear / Vercel / Geist" aesthetic is what every other 2026 SaaS imitates. If we want a *pioneer-feeling* prompt vault embedded inside an Electron terminal session window, this is the most defensible visual language we can pick because:

1. It is **dense by default**. Linear's issue list crams enormous information density into a single row without ever feeling cluttered — exactly what we need for a vault that lists 30+ `.md` files at once.
2. It is **dark-first**. The EZvibes app already lives next to a black PowerShell PTY — Linear's dark palette won't fight that. Light mode is treated as a derivative theme, not the canonical one.
3. It uses **luminance hierarchy, not weight hierarchy**. Headings don't get bolder; the *background* gets slightly lighter to lift the active row. This is critical for a small panel where bold text would eat the row.
4. It uses **OKLCH-driven theming** — change a single accent variable and the entire panel re-tints (purple Claude vs teal Codex, perfectly).
5. The **subtle 1 px line** and **ghost button** are its calling cards. Combined with Geist Mono for file paths, this looks immediately like a tool a senior infra engineer would ship.

Mapping to the vault:
- The vault panel = Linear's "Triage" inbox in style.
- Each `.md` row = Linear's issue row pattern (`[icon][title][meta-chip-row][right-aligned meta]`).
- The action button (your red-arrowed "paste") = Geist's `secondary` Button with the accent applied to the leading icon only.
- The "Vault" header = Linear's `font-variant: small-caps; letter-spacing: 0.11em` group header.
- The hover row = Linear's `oklch(from var(--bg) calc(l + 0.04) c h)` lift.
- The keyboard shortcut chips = Geist `<kbd>` style with a 1 px inner border.

## 1. The Linear color system — what it actually is in 2026

Linear's 2024 redesign (the "Inverted L" chrome) moved their CSS theme engine from HSL to **LCH**, and their May 2026 refresh ("A calmer interface for a product in motion") pushed it further toward **OKLCH** with a real-time token tool built using Claude Code.

### 1.1. The accent: indigo, not purple

Despite being called "Linear purple" for years, the actual brand accent is closer to a saturated indigo:

```
Primary accent  #5E6AD2   rgb(94, 106, 210)   hsl(232, 55%, 60%)   oklch(57.2% 0.143 270.5)
Accent hover    #6872D9   rgb(104, 114, 217)
Accent glow     rgba(94, 106, 210, 0.3)        // used in multi-layer button shadows
Header h2 fg    #F7F8F8                         // off-white, body / page heading
Body / meta fg  #95A2B3   rgb(149, 162, 179)   // mid-gray, used for both body copy and uppercase eyebrows
Button fg bg    #4551B5                         // pressed / filled state of the accent
```

The interesting thing: this *same* `#95A2B3` is used for both the section-header eyebrow ("HEADER 1") and for body copy. The hierarchy is generated by size + letter-spacing, not by color.

### 1.2. The three-variable theme model

Linear's 2024 rewrite reduced themes from 98 hard-coded variables to **three**: base color, accent color, and contrast. Everything else is derived. The exact pattern they ship in their app:

```css
:root {
  --base:     oklch(20%  0.012 280);   /* dark gray-purple canvas */
  --accent:   oklch(57%  0.143 270);   /* the indigo */
  --contrast: 1;                        /* multiplier: 1 = normal, 1.6 = high-contrast a11y */
}

/* derived surfaces, all relative to --base */
--bg-page:   var(--base);
--bg-elev-1: oklch(from var(--base) calc(l + 0.03) c h);  /* sidebar         */
--bg-elev-2: oklch(from var(--base) calc(l + 0.06) c h);  /* card / panel    */
--bg-hover:  oklch(from var(--base) calc(l + 0.04) c h);  /* row hover       */
--bg-active: oklch(from var(--base) calc(l + 0.08) c h);  /* row selected    */

/* derived borders */
--border-subtle: oklch(from var(--base) calc(l + 0.10) c h);
--border-strong: oklch(from var(--base) calc(l + 0.18) c h);

/* derived text */
--fg-primary:   oklch(96% 0.005 270);  /* near-white                       */
--fg-secondary: oklch(72% 0.018 270);  /* meta / timestamps / file paths   */
--fg-tertiary:  oklch(50% 0.018 270);  /* disabled / placeholder           */

/* derived accent-on-hover (the magic one) */
--accent-hover: oklch(from var(--accent) calc(l + 0.05) c h);
--accent-soft:  oklch(from var(--accent) calc(l + 0.10) calc(c * 0.4) h / 0.15);
```

The `oklch(from var(--accent) ...)` relative-color syntax shipped in Chromium 119 (Nov 2023). Electron 33 uses Chromium 130 — **we can use this directly with no polyfill**.

### 1.3. Why OKLCH, not HSL

In HSL, `hsl(60, 100%, 50%)` (yellow) and `hsl(240, 100%, 50%)` (blue) have the *same* lightness value but yellow looks like noon and blue looks like midnight. In OKLCH, lightness is perceptually uniform — equal lightness numbers = equal perceived brightness. This is the whole reason Linear can generate themes from a single base color and have them all look "right." Tailwind v4 (April 2025) shipped with OKLCH as the default color space for the same reason.

For our vault:
- Claude tab tint = `oklch(72% 0.12 75)` (amber, matches the existing chip color)
- Codex tab tint = `oklch(68% 0.10 195)` (teal, matches the existing chip color)
- A single `--accent` swap repaints the entire vault panel.

### 2.1. The Inter UI / Inter Display split

Linear started shipping **Inter Display** (the optical-sized variant tuned for >20 px) in headings during the 2024 refresh, while keeping **Inter** (or the original "Inter UI") for ≤14 px. Inter Display has tighter letter-spacing baked in. For our vault we don't need Inter Display — everything in the vault is ≤16 px, so plain Inter is correct.

### 2.2. Linear's typography scale (from the 2025 refresh blog + Plane.so clone CSS)

```
9px   — chip counters, badge superscripts
11px  — input hints, footer copyright
12px  — uppercase eyebrows, meta text, timestamps, chip labels
13px  — table cells, tab chip labels in the redesign
14px  — body, list row titles (most-used size)
16px  — sidebar nav items, big-screen body
20px  — modal titles, section headers
24px  — page titles
32px  — empty-state hero
```


### 2.3. The 4 px / 8 px spacing scale

Linear does **not** use a grid in the Bootstrap sense. They use **an 8 px spacing scale** (with 4 px half-steps): 4, 8, 12, 16, 24, 32, 64. The vault should use the same:

```css
--space-1: 4px;   /* chip padding, kbd inset */
--space-2: 8px;   /* row icon → text gap */
--space-3: 12px;  /* row vertical padding, sidebar pad */
--space-4: 16px;  /* panel padding, button padding */
--space-6: 24px;  /* section gaps */
--space-8: 32px;  /* hero-ish gaps */
```

## 3. The Linear list row — the most copied UI primitive in 2026

This is **the** core pattern for our vault. Every prompt `.md` is a list row.

### 3.1. Visible anatomy

```
┌────────────────────────────────────────────────────────────────────────┐
│  [▢] [icon]  Filename.md  [tag] [tag] [tag]         3d ago      [⋯]   │
└────────────────────────────────────────────────────────────────────────┘
   |    |        |             ^                          ^         ^
   |    |        +--14px/500   |                          |         +-- ghost menu, only on hover
   |    |                      +-- inline chips, 12px      +-- right-aligned meta
   |    +-- 14×14 svg, fg-secondary, accent on hover
   +-- optional checkbox, only visible on row hover (shifts in)
```

Row height: **32px** (Linear's default density). Linear also offers `40px` (medium) and `48px` (low) via display settings — we should ship 32 px and 40 px modes.

### 3.2. CSS that captures the row hover transition

```css
.row {
  display: grid;
  grid-template-columns: 16px 16px 1fr auto;
  align-items: center;
  gap: 8px;
  height: 32px;
  padding: 0 12px 0 8px;
  border-radius: 6px;
  cursor: pointer;
  color: var(--fg-primary);
  /* the magic — single property transition, fast */
  transition: background-color 80ms ease-out;
}

.row:hover {
  background: var(--bg-hover);   /* +4% lightness in OKLCH */
}

.row[data-selected="true"] {
  background: var(--bg-active);  /* +8% lightness */
  /* and a 1px-inset accent border to mark it */
  box-shadow: inset 0 0 0 1px var(--accent-soft);
}

/* meta column is muted by default, brightens on row hover */
.row .meta { color: var(--fg-secondary); transition: color 80ms; }
.row:hover .meta { color: var(--fg-primary); }

/* hover-only chrome — checkbox slides in, ⋯ menu fades in */
.row .checkbox, .row .menu {
  opacity: 0;
  transition: opacity 80ms;
}
.row:hover .checkbox, .row:hover .menu {
  opacity: 1;
}
```

### 3.3. Key behaviors

- **Selecting a row is instant** — never wait for a network call before highlighting (Geist Tabs guideline applies equally to rows).
- **Multi-select via Shift+Click and Cmd+Click** is mandatory if you want the vault to feel like Linear.
- **Keyboard navigation** with `j` / `k` (vim style) and arrow keys, with the same `:hover` styles applied to the *focused* row. Use `:where(.row:hover, .row:focus-visible)`.
- **Density toggle** — store `data-density="compact" | "default" | "comfortable"` on the panel root and switch row height + font size in CSS.

## 4. Vercel + Geist — the system, not just the font

### 4.1. Geist's foundations (what's actually documented)

Geist is Vercel's design system. There are **5 foundations**: Color System, Typography, Layout (grid), Icons, Component overview. And **29+ components** including Button, Tabs, Modal, Drawer, Combobox, Data table, Tooltip, Tree view, Empty state, Snackbar.

Geist's color system is built on **10 scales** with 12 steps each (Radix-style):
- `gray`, `gray-alpha` — neutrals (gray-alpha is transparency-based, great for overlays)
- `blue`, `red`, `amber`, `green`, `teal`, `purple`, `pink`

Steps 1–12 map semantically:
```
Step 1     App background
Step 2     Subtle background (sidebar, cards)
Step 3     UI element background (default)
Step 4     UI element background (hover)
Step 5     UI element background (active)
Step 6     Subtle border
Step 7     UI element border (hover)
Step 8     Solid border / focus ring
Step 9     Solid background (accent fills like primary button)
Step 10    Solid background (hover)
Step 11    Low contrast text (secondary)
Step 12    High contrast text (primary)
```

This is the *Radix scale* (Geist is essentially Radix Colors + custom hues). For our vault we can use the published Radix Colors npm package and it will look 1:1 Vercel.

### 4.2. Geist Mono — what it does for file paths

Geist Mono is designed for code editors, terminals, diagrams. The killer feature is **programming ligatures**: `=>`, `!=`, `>=`, `->` become single glyphs. This is enabled via:

```css
.path {
  font-family: "Geist Mono", "JetBrains Mono", ui-monospace, monospace;
  font-feature-settings: "calt" 1, "ss01" 1, "ss02" 1, "zero" 1;
  /* calt = contextual alternates (the ligatures)
     ss01-ss20 = stylistic sets (e.g. ss02 = single-story 'a' in some fonts)
     zero = slashed zero, very useful in mono for distinguishing 0 from O */
}
```

For our vault, file paths and the kbd-chip shortcuts should be Geist Mono. The size guideline:
- Standard 1080p display: **12–14 px**
- 4K / Retina: **11–13 px** (the high-density glyphs are sharper, so smaller is fine)

### 4.3. Geist Sans variable axis

Geist Sans is a single variable font with a `wght` axis from **100 (Thin) to 900 (Black)** in nine named weights:
`Thin 100 / Ultra Light 200 / Light 300 / Regular 400 / Medium 500 / Semi Bold 600 / Bold 700 / Black 800 / Ultra Black 900`

For UI you want only **400 / 500 / 600**. 700+ is for marketing pages and 200–300 is for hero numerals.

### 4.4. Installing Geist in our Electron renderer

Two options:

**A. npm package (preferred — full OpenType features)**
```bash
npm i geist
```
```css
@import "geist/font/sans.css";
@import "geist/font/mono.css";

:root {
  --font-sans: "Geist", -apple-system, "Segoe UI", system-ui, sans-serif;
  --font-mono: "Geist Mono", "JetBrains Mono", ui-monospace, "SFMono-Regular", monospace;
}
```

**B. Self-hosted .woff2** (we control the file, no network)
Download from `https://vercel.com/font` or the GitHub repo `vercel/geist-font/releases` and drop into `renderer/fonts/`.

## 5. The Geist Button — exact spec we can clone

Geist's Button has three "types" (primary/secondary/tertiary) × four "intents" (default/success/error/warning) × three sizes (sm/md/lg). The relevant ones for the vault:

```css
/* secondary button — what the row-level "Paste" action should be */
.btn-secondary {
  display: inline-flex;
  align-items: center;
  gap: 6px;
  height: 28px;                     /* sm */
  padding: 0 10px;
  font: 500 13px/1 var(--font-sans);
  color: var(--fg-primary);
  background: transparent;
  border: 1px solid var(--border-subtle);
  border-radius: 6px;
  cursor: pointer;
  transition: background-color 80ms, border-color 80ms;
}
.btn-secondary:hover {
  background: var(--bg-hover);
  border-color: var(--border-strong);
}
.btn-secondary:active {
  background: var(--bg-active);
}

/* primary button — for the "Save hand-off" action */
.btn-primary {
  height: 28px;
  padding: 0 12px;
  font: 600 13px/1 var(--font-sans);
  color: white;
  background: var(--accent);                          /* #5E6AD2-style */
  border: 1px solid color-mix(in srgb, white 10%, var(--accent));
  border-radius: 6px;
  box-shadow:
    inset 0 1px 0 rgba(255,255,255,0.12),            /* top highlight */
    0 1px 2px rgba(0,0,0,0.25),                       /* shadow under */
    0 0 0 1px var(--accent-soft);                     /* outer glow ring */
}
.btn-primary:hover {
  background: var(--accent-hover);                    /* +5% lightness */
  box-shadow:
    inset 0 1px 0 rgba(255,255,255,0.18),
    0 2px 6px rgba(94,106,210,0.35);                  /* the indigo glow */
}

/* ghost button — for the row's ⋯ menu trigger */
.btn-ghost {
  width: 24px; height: 24px;
  display: inline-flex; align-items: center; justify-content: center;
  background: transparent;
  border: none;
  border-radius: 4px;
  color: var(--fg-secondary);
  cursor: pointer;
}
.btn-ghost:hover {
  background: var(--bg-hover);
  color: var(--fg-primary);
}
```

The **multi-layer shadow** on the primary button is the single most recognizable Vercel/Linear visual signature. Three stacked shadows: inset highlight, drop shadow, outer accent ring.

## 6. The Geist Tabs component (already shipped in our app's chip strip)

The user's session window already has Chrome-style tabs (`CLAUDE 2`, `CODEX 3`). The Geist version has these specifics:

```
hoverHeightRatio: 0.7       (the hover pill is 70% of the chip height)
hoverWidthRatio:  1.15      (and 115% of chip width — slightly wider than text)
align:            left      (default)
leftSpace:        12px
```

The hover behavior: a single absolutely-positioned `<div>` slides between tab positions using a Framer Motion shared layout animation (`layoutId="active-tab-bg"`). When you hover a tab, the pill background **morphs** between positions instead of fading. This is the "animated underline that follows the cursor" pattern that Vercel popularized in 2022 and that Apple, Linear, and Notion have all since adopted.

Implementation in vanilla JS (we don't have Framer Motion):

```js
// pseudo-code for the morphing pill
function moveActivePill(tabEl) {
  const pill = document.querySelector('.active-pill');
  const rect = tabEl.getBoundingClientRect();
  const parentRect = tabEl.parentElement.getBoundingClientRect();
  pill.style.transform = `translateX(${rect.left - parentRect.left}px)`;
  pill.style.width = `${rect.width}px`;
}
```

```css
.active-pill {
  position: absolute;
  inset: 0 auto 0 0;
  height: 100%;
  background: var(--bg-active);
  border-radius: 6px;
  z-index: 0;                          /* behind the tab labels */
  transition: transform 220ms cubic-bezier(0.32, 0.72, 0, 1),
              width     220ms cubic-bezier(0.32, 0.72, 0, 1);
}
```

The easing `cubic-bezier(0.32, 0.72, 0, 1)` is Linear's signature curve — a strong out-quint feel.

## 9. The Linear **status pill** pattern (for vault tags)

In Linear every issue has a small status icon (the donut). In our vault, every prompt should have an inline metadata chip set — one for type (`prompt`, `handoff`, `claude.md`), one for last-edited (`now`, `5m`, `3d`).

```css
.chip {
  display: inline-flex; align-items: center; gap: 4px;
  height: 18px;
  padding: 0 6px;
```

## 10. Animation language — the curves Linear and Geist use

Linear and Geist motion are dominated by **fast, out-curves**. Not bouncy. Not springy. Snappy.

```css
:root {
  /* the only easing curves you should use */
  --ease-out:       cubic-bezier(0.32, 0.72, 0, 1);   /* default for most things */
  --ease-out-fast:  cubic-bezier(0.4, 0, 0.2, 1);
  --ease-in-out:    cubic-bezier(0.4, 0, 0.6, 1);
  --ease-spring:    cubic-bezier(0.34, 1.56, 0.64, 1); /* used sparingly for "joy" */

  /* durations */
  --dur-instant: 80ms;     /* row hover, chip hover */
  --dur-fast:    160ms;    /* button hover, tab switch */
  --dur-base:    240ms;    /* panel open, popover */
  --dur-slow:    400ms;    /* page transition (rare) */
}
```

For the vault:
- Row hover: 80 ms color
- Vault panel slide-in (from right edge): 240 ms transform + 240 ms opacity
- File-watch new-file pop: a 320 ms scale from 0.95 → 1 with the spring curve
- "Pasted to terminal" toast: 160 ms in, hold 1500 ms, 160 ms out

## 11. The "paste to terminal" interaction — pioneer-level design

This is the headline interaction. The user clicks a vault row and the markdown content is injected into the active PTY. The visual feedback options ranked by pioneer-ness:

### 11.1. Bronze (table stakes)
- Click row → terminal receives text → a transient toast: "Pasted prompt-name.md → CLAUDE tab"

### 11.2. Silver (Linear-tier)
- Click row → the row briefly flashes the accent color (200 ms), THEN the terminal scrolls down and the text appears with a 1-character/16 ms typewriter effect.
- Visually it looks like the content is *transported* from the vault row into the terminal.

### 11.3. Gold (Vercel toolbar tier)
- Click row → a "ghost" copy of the row's title detaches and **flies** along a quadratic Bezier curve from the row's center to the active terminal tab. Uses the View Transitions API:

```js
async function pasteWithFlight(row, terminalEl) {
  if (!document.startViewTransition) {
    paste(row); return;
  }
  // give the row a unique view-transition-name
  row.style.viewTransitionName = 'paste-flight';
  await document.startViewTransition(() => {
    row.style.viewTransitionName = '';
    terminalEl.style.viewTransitionName = 'paste-flight';
    paste(row);
    // after paste, remove the name so the next paste can reuse it
    requestAnimationFrame(() => { terminalEl.style.viewTransitionName = ''; });
  }).finished;
}
```

`document.startViewTransition()` is shipped in Chromium 111+ (Electron 30+). We're on Electron 33, fully supported. The browser auto-animates between the row position and the terminal position. This is **the** 2026 desktop-app flourish — Arc, Linear, Notion all use View Transitions for cross-component animation now.

### 11.4. Platinum (pioneer)
- Same as Gold, **plus** a *typing inertia*: the markdown content lands at the prompt cursor and is "typed" character-by-character at 8 ms/char into the PTY, so the user sees it stream into the terminal as if they were typing it. (PTY accepts a string write — we throttle the write to the PTY ourselves.)
- A 1-px scanline overlay sweeps down the terminal once during the typing to make it feel "received." Reference: Raycast's clipboard history paste animation.

For EZvibes, **silver + a watered-down flight (just an opacity fade + slight Y-translate of a clone)** is the sweet spot. The Platinum approach is fun but it adds latency that defeats the "instant paste" mental model.

## 13. Five "pioneer-level" UI moves to consider for the vault

The user asked for pioneer-level styling. Here are five 2026 ideas the Linear/Vercel side of the industry is converging on:

### 13.1. **Living preview on hover**
When the user hovers a row for ≥250 ms, a tooltip-style **right-floating preview** opens showing the first 12 lines of the `.md` rendered as syntax-highlighted text. Linear does this for issues; Vercel does it for deployments. The preview uses Geist Mono and a 1-px border. Implementation: a `<details popover>` or floating-ui anchored popover. Crucially, it doesn't block click — clicking through the preview still pastes.

### 13.2. **Right-to-left "appearance" of new hand-offs**
When the file watcher detects a new `handoff.md` written by another Claude session, the row **slides in from the right** with a 320 ms `cubic-bezier(0.32, 0.72, 0, 1)` and a one-time accent border that fades over 1.6 s. This is Linear's "new comment" animation. Combined with a green pulse on the vault-footer dot, it creates an unmistakable "another session just delivered something to you" moment.

### 13.3. **The "vault flash"**
When a paste lands, the entire vault root briefly gets `box-shadow: inset 0 0 0 1px var(--accent)` for 180 ms. This is Vercel's "deployment success" flash. Pairs perfectly with the View Transition flight in §11.3.

### 13.4. **Pinch-zoom density**
`Ctrl + scroll` over the vault adjusts `data-density`. The CSS variables `--row-height` and `font-size` change smoothly via a transition. Linear's display options force users into a settings menu — *we* can do it as a gesture and it feels miraculous.

### 13.5. **`/` to filter from anywhere in the panel**
Even when focus is on a row, pressing `/` jumps to the search input. Pressing `Esc` from the search jumps back to the previously focused row. This is the Linear / GitHub / GitLab keyboard convention.

## 14. The fastest path to ship: a 6-file diff

For our codebase (Electron 33, vanilla JS, single-IIFE renderer, ~1200 lines), the smallest viable diff to ship the Linear-style vault is:

1. **`renderer/index.html`** — add the `<aside class="vault">` markup inside each session window's main content region. Total: ~50 lines.
2. **`renderer/styles.css`** — append the token block + the `.vault*` rules from §12. Total: ~250 lines.
3. **`renderer/app.js`** — add a `Vault` module: `loadFolder(path)`, `renderRows()`, `bindRowClick(handler)`. Use `chokidar` (already in node-pty's transitive deps as `chokidar` is not, but `fs.watch` recursive works on Windows). Total: ~150 lines.
4. **`main.js`** — add IPC channels `vault:list`, `vault:watch`, `vault:read`. Returns markdown content. Total: ~80 lines.
5. **`preload.js`** — expose `vault.list`, `vault.watch`, `vault.read`, `vault.paste` on `window.ezvibes`. Total: ~10 lines.
6. **`renderer/fonts/`** — drop Geist Sans + Geist Mono `.woff2` files. Loaded via `@font-face` in `styles.css`.

The paste mechanism is one line in `app.js`:
```js
window.ezvibes.writeTerminal(activeTabId, markdownContent);
```
The PTY treats it as typed input — Claude / Codex sees it as the user pasting.
